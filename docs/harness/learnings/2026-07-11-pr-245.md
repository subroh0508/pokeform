## ✅ Keep（継続したいこと）

- **ADR 追従漏れを型エラーで機械検出できた**: ADR 0045（#244）の gender メガ統合の副作用（per-reg `speciesDex` 生成が単一メガ形態を 2 回 emit）が `tsc --noEmit` の TS1117（重複キー）として M-A フル rollout で顕在化。tsc-only 検証（ADR 0010）の狙いどおり、実行時でなく型で追従漏れを弾けた。
- **修正が根本原因に対する最小 diff**: 症状（重複キー）を場当たり抑止せず、原因（base ごとに mega を emit するループ構造）を `basesByMega` Map で mega id ごとに group 化して 1 度だけ emit する形に正した。1 ファイル +24/-9 に収まり、通常メガ（`sid == baseSpecies`）の出力は不変。
- **moves union の意味的正しさを movepool 差異の裏取りで担保**: ♀♂で movepool が異なる（♀: extrasensory/future-sight 固有・♂: imprison 等固有）事実を根拠に、どの gender から進化しても legal moveset を弾かないよう全 base の union を採用。単一 base は従来の `speciesMoves` 参照を維持し挙動不変。
- **end-to-end で生成物まで検証**: `pnpm verify` に加え M-A 全抽出 → `generate:data` → `meowstic-mega` が index.ts に 1 エントリ（moves=union）→ `check:regulation` 整合 → TS1117 解消まで実地確認。scripts はカバレッジ include 外という制約を end-to-end 検証で補った。
- **union を決定論的に生成**: `new Set` + `.sort()` で movepool union を安定順序にし、生成物の再現性（git diff の安定）を確保。code-review でもこの点を明示的に評価。

## ⚠️ Problem（詰まった点・制約）

- **ADR 0045 の統合が per-reg 生成側の追従を伴わずマージされた**: #244 は型表現（gender メガ単一形態）を変えたが、それを消費する `scripts/generate.ts` の per-reg `speciesDex` 生成が旧前提（base ごとに mega emit）のままで、M-A フル rollout で初めて TS1117 が露見。型変更 PR の「下流生成コードの追従」がチェックリスト化されていない。
- **scripts/ がカバレッジ include 外ゆえ回帰を unit test で固定できない**: `generate.ts` の重複排除・union ロジックはテストで守られず、end-to-end 検証に依存。同種のバグ（gender メガ以外の複数 base メガが将来出た場合）が再発しても自動では捕れない。
- **バグの発現が「M-A フル rollout」という別作業の副産物として出た**: 統合メガの dedup 欠陥は、限定 placeholder では単一メガ base しか無く顕在化せず、フル roster 投入で初めて複数 base が同一メガへ進化する条件が揃って露見した。データ規模依存で潜伏する型エラーは、小さな検証データでは事前に捕れない。
- **`sids[0] as string` の cast が残った**: noUncheckedIndexedAccess 対応の cast で `length === 1` ブランチ内ゆえ安全だが、分割代入等でも表現でき型安全性の表現に改善余地（code-review でも nit 指摘）。
