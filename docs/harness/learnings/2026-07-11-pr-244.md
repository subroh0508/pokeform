- **責務分割の明確化**: `canonicalFormId` を base 種族 form 専任に戻し、gender メガ畳みを `mega-fields.ts` の `megaFormId` へ分離。ADR 0044 で `canonicalFormId` に載せていた `-f-mega`/`-m-mega` エントリを `FORM_SLUG_RENAME` から撤去し、docstring も追従更新した(doc-code 乖離を残さない)。
- **テストを統合方針へ全面追従**: 畳み(`megaFormId`)・gender 別 base 導出(`megaEvolveBaseId` F→`-female`/M→`-male`)・両 base 紐付け(`groupMegaByBase` dedup)・items `megaSpecies` を新方針の期待値へ更新し、非 gender メガ(`charizard-mega-x`)の no-op も固定。カバレッジ 100%(233 tests)維持。

## ⚠️ Problem（詰まった点・制約）

- **generated ドリフトが機械ゲート外で長期未検出だった**: #241 が未再生成だった 34 ストーンの `src/generated/languages/items.ts` ドリフト(+238 行)を本 PR で併せて解消したが、これは `pnpm verify`(型/カバレッジ/Biome)が `generate:data` の再生成 diff を検出しないため #241 で見逃されていた。SoT→generated の同期漏れを機械ゲートが拾えない構造的な穴。
- **統合メガ名が PokeAPI backfill 対象外で skill 手著述依存**: `meowstic-mega` は PokeAPI `pokemon-form`(gender 別しか持たない)から backfill できず、`languages/mega.yaml` を skill 手著述で埋めた(ADR 0043 例外)。手当てを漏らすと `requireNames` で generate が落ちる脆さがあり、gender メガが増えるたび手作業が必要。
- **gender メガ判定が forme id サフィックス形状に依存**: `GENDER_MEGA_SUFFIX = /-(f|m)-mega$/` は現状 meowstic のみで正しいが、新種で別サフィックス(例 `-female-mega` を showdown が直接持つ等)が来ると拡張が要る。判定が id 形状の暗黙契約に乗っている。
- **mega-specs.baseSpecies の逆参照が非対称**: 単一逆参照ゆえ canonical(♂=`meowstic-male`)のみ保持し、♀ base は `megaEvolvesTo`(species-specs / per-reg)側でのみ表現する。この非対称は型で表現されず(reciprocity 型検証なし)、`megaEvolvesTo` が `readonly string[]` である前提に依存して成立している。
- **fix と別関心(#241 ドリフト解消)が同一 PR に混在**: gender メガ統合 fix に 34 ストーンの generated 同期が混ざった。PR body に明記済みで許容されたが、レビュー粒度としては別関心。
