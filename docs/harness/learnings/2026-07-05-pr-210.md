## ⚠️ Problem（詰まった点・制約）

- **`allowed-tools` に本文で直接使わないエントリ（`Bash(node scripts/*)` / `Bash(node src/cli/*)`）が残った**。cross-agent フォールバックは `pnpm *` 経由で表現され、`node scripts/*` 直呼びは本文に現れない。author-static-data からの踏襲だが最小権限の観点で縮小余地がある（harness-review nit）。
- **`data-pipeline.md` の追記が skill 手順をやや全量インライン再記述した**（reset → dispatch → 照合 → check → generate → 静的著述 → reviewer 依頼を 1 行に列挙）。末尾に skill ポインタがあり規約範囲内だが、将来 skill 手順が変わると rule 側の再記述が追従漏れになる僅少リスクがある（harness-review nit）。
- **skill 本文が「dispatch した PR をどう追跡するか」を `gh pr list --label` 程度の粒度に留めた**。showdown-sync が複数 reg で走ると run_id サフィックスのブランチが並ぶが、対象 PR の同定手順は薄い。Phase 9 の実投入で手順の実効性が初めて検証される（本 phase は skill のみで end-to-end 未実行）。
- **前提ゲートの「全件名辞書が満たされているか」の判定基準が定性的**。「空 / 未整備なら」という表現で、機械的な充足チェック（件数閾値等）は持たない。判断をエージェントに委ねる設計だが、境界ケース（部分投入済み）での挙動が曖昧。
