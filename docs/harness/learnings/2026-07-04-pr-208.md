## ⚠️ Problem（詰まった点・制約）

- **Phase 6 基盤の append 欠落バグが Phase 7（初回全件実行）で初めて顕在化**した。`materialize`（`sync:ja-names`）は既存エントリの backfill のみで**未記録 id を append しなかった**。ADR 0041 / data-pipeline rule は「raw → languages へ ja/en を **append**/既存尊重転記」と明記していたが実装が追随しておらず、`sync` が `filled 0` を返して languages が全く伸びない状態だった。基盤 phase の受け入れ検証が「全件投入を実際に一度 end-to-end で回す」までカバーしていなかったため、bug がデータ投入 phase まで潜伏した。
- **PokeAPI が ja を持たない id（76件）と NameEntry(ja/en 必須) が衝突**した。GO 専用特性（`is_main_series:false` 60）+ 未ローカライズ新特性（`eelevate`/`fire-mane` 2）+ Legends Arceus クラフト球（`la*-ball` 等 14）。ADR 0041 は「各エントリに ja/en が揃う（PokeAPI 非存在分は手作業）」としつつ、実 API が `pokemon-species`/`item`/`ability` の list に **ja 未収録の id を含む**現実を想定していなかった。generate は orphan を許容するが tsc は emit された literal に ja を要求するため build が落ちた。
- **「データのみ PR・pokemon-data-reviewer のみ」という Phase 7 の分離設計が、基盤バグにより崩れた**。結果として scripts/rule/data を跨ぐ PR になり、code-review も追加で必要になった。基盤（Phase 6）とデータ投入（Phase 7）を別 phase に割った意図（レビュー面の分離）が、Phase 6 の検証不足のしわ寄せで一部損なわれた。
- **「全件」の定義に注記が必要だった**。`rotom-wash` 等 pokeform 固有フォーム種族は PokeAPI `pokemon-species` 列挙の外にいるため、live count（1025）と languages（1026）が 1 件ズレる。「全件辞書」を語る際の基準（= PokeAPI list 列挙）が skill / doc に明示されていなかった。
- **`dynamax-crystal-*`（216件）の ja/en が `★XxxNNN` カタログコード**で、一見 placeholder / 文字化けに見える。PokeAPI が全言語で未翻訳の実データであり正しいが、将来「壊れたデータ」と誤認される risk がある（champions specs 未参照の orphan）。
