## ✅ Keep（継続したいこと）

- **root cause を biome の設定挙動まで特定**: `pnpm lint`（`biome check .` + `useIgnoreFile:true`）が workspace 内へ clone された pokemon-showdown ツリーを走査して 1468 errors で落ちる、という失敗を「lint 対象範囲の問題」まで正しく切り分けた。表層のエラー数に振り回されず、vendor ツリーが lint/track 対象に混入している構造要因へ辿り着いた。
- **`.gitignore` 追加が git track と biome lint の両方を同時に解決する点を活用**: `useIgnoreFile:true` により biome が `.gitignore` を尊重するため、1 行の ignore 追加で「git 追跡外」と「lint 走査外」を一挙に満たした。副作用の少ない最小修正を選べた。
- **修正の実効性をダミー不正ファイルで裏取り**: ignore 追加後、pokemon-showdown 配下にわざと lint 違反ファイルを置いても `pnpm lint` が 127 files のみ検査で緑になることを確認し、「ignore が効いている」ことを推測でなく実挙動で検証した。
- **vendor 扱いの意図を diff コメントに明記**: `.gitignore` の追加行に「showdown-sync.yml が workspace 内へ clone・vendor・lint/track 対象外」と理由を残し、後から見た人が「なぜここに showdown があるのに ignore なのか」を追える。
- **最小 diff（1 file +3/-0）で CI blocker を解消**: スコープを CI 修正に限定し、無関係な整理を混ぜずに 1 コミットで green を回復した。

## ⚠️ Problem（詰まった点・制約）

- **M-A rollout が generate を通過して初めて表面化した**: pokemon-showdown clone が lint を落とす問題は、解禁データ投入（M-A rollout）が generate まで進んで workspace に clone が残る経路が踏まれるまで潜在していた。vendor ツリーの混入は先んじて予見しにくく、CI 失敗として遅れて顕在化した。
- **biome の `useIgnoreFile:true` × workspace 内 clone の相互作用が非自明**: 「`biome check .` が clone した外部リポジトリ全体を走査する」挙動は、`.gitignore` に載っていない限り自動では防げない。CI ワークフローが workspace 内へ vendor を clone する設計と lint 範囲の前提が暗黙に結合していた。
- **回帰を機械的に守る仕組みが無い**: 今後別の vendor ツリー（別ツール clone 等）が workspace 内に増えたとき、同じ lint 混入が再発しうる。ignore 追加は個別対処で、「workspace 内 vendor は ignore する」という原則がどこにも成文化されていない。

- **[skill] author-regulation-data / verify-showdown-pr の showdown clone を扱う手順に「clone 先が `.gitignore` 済みか（lint/track 対象外か）」の確認を 1 項足す**。workflow が workspace 内へ clone する経路を踏むとき、lint 混入を事前に潰せるようにする。
